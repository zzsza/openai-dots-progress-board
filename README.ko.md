# OpenAI Dots Progress Board

[English](README.md)

OpenAI Dots와 대화하면서 맡긴 일의 진행상황과 반복 예약을 기록하는 개인용 보드입니다. 연결된 dot이 작업 시작, 진행 상태 변경, 응답 대기, 완료와 중단 시 보드를 갱신합니다.

## 화면

![진행상황 보드 예시](docs/screenshots/progress-board.png)

## 볼 수 있는 내용

- 지금 하는 일, 마지막으로 보고한 일, 다음 행동과 결과
- 내 답변이나 외부 조건을 기다리는 이유
- 기존 cron과 반복 예약에 대해 보고받은 정보, 확인 가능한 예약 주기, 기준 시간대, 활성 여부, 다음 실행과 최근 실행 시각
- 마지막 보고 시각과 오래 갱신되지 않은 기록
- 검색, 직접 기록과 수정, 최근 변경 이력, 보관과 복원

보드는 `report_activity`로 전달한 내용이나 직접 작성한 기록을 저장합니다. 기존 대화와 예약을 자동 수집하지 않습니다. 화면의 예시 4건은 실제 데이터베이스에 저장하지 않습니다.

## 다른 사람이 사용하는 방법

**각자 자신의 계정에 새로운 비공개 Sites 인스턴스를 배포해서 사용합니다.** 인스턴스마다 저장소와 플러그인이 별도로 만들어집니다. 자신의 보드 주소와 플러그인을 사용합니다.

1. 이 공개 저장소를 복제하거나 포크합니다.
2. ChatGPT Work 또는 Codex에서 복제한 프로젝트를 열고 다음과 같이 요청합니다.

   > 이 프로젝트를 내 계정의 새로운 비공개 Sites로 배포해줘. `.openai/hosting.json`에 `project_id`가 없으면 새 Site를 만들고 그 ID를 저장해. D1 저장소와 기존 마이그레이션을 적용하고 MCP 플러그인도 연결할 수 있게 준비해줘. 다른 사람의 Site ID, 데이터, 인증값을 복사하지 마.

3. 배포된 사이트의 플러그인을 자신의 ChatGPT 계정에 설치하거나 연결합니다.
4. dot 대화에서 해당 플러그인을 선택하고 아래 지시문을 전달합니다. 보드의 **Dots 연결 안내**에서도 연결 방법을 확인할 수 있습니다.
5. dot에게 작은 일 하나를 기록해달라고 요청하고, 기록을 다시 읽어 실제 연결을 확인합니다.

GitHub 배포용 소스의 `.openai/hosting.json`에는 개인 Site ID를 포함하지 않습니다. `.openai/hosting.example.json`은 새 인스턴스에 사용할 설정입니다. 자신의 배포가 끝난 뒤 실제 `project_id`는 그 인스턴스의 배포 소스에 보관합니다.

## dot에게 전달할 복사용 지시문

보드 플러그인을 연결한 뒤 다음 지시문을 복사해서 dot에게 전달하세요.

```text
앞으로 내가 맡긴 작업의 시작, 진행 상태 변경, 응답 대기, 완료, 중단을 연결된 보드에 기록해줘. 같은 작업은 같은 카드를 갱신하고, 다음 행동, 대기 이유, 결과 링크를 남겨줘. 내가 요청한 자동화를 생성하거나 변경하거나 중단했을 때도 실제로 확인한 예약 정보와 상태를 보드에 기록해줘. 예약 주기, 시간대, 활성 여부, 최근 실행, 다음 실행 시각은 확인 가능한 값만 사용하고, 제공되지 않은 값은 미제공으로 표시해줘. 잡담과 민감한 정보는 제외하고, 실행이나 완료 여부를 추측하지 마.
```

**GitHub에 README를 올리는 것만으로 다른 사용자의 dot에 지시가 적용되지는 않습니다. 각 사용자가 자신의 보드를 연결하고 dot에게 지시문을 전달해야 합니다.** 다른 대화에서도 사용하려면 해당 dot의 사용자 지침에 저장하도록 요청하고 실제로 따르는지 확인하세요. [AGENTS.md](AGENTS.md)에는 이 저장소에서 작업하는 에이전트의 보고 루틴이 있지만, 다른 사용자의 dot을 설정하지는 않습니다.

먼저 기존 기록을 읽고 같은 목표에는 같은 고정 `id`를 사용합니다. 실행 전에는 `planned`, 실제 실행이 시작되면 `working`, 응답이나 외부 조건이 필요하면 `waiting`, 완료를 확인한 뒤에는 `done`, 중단하거나 일시정지하면 `paused`를 사용합니다. 대기할 때는 구체적인 `waitingFor`, 다음 행동은 `nextStep`, 결과가 있으면 `resultUrl`을 남깁니다. 첫 기록은 `get_activity`로 다시 읽어 저장을 확인하고, 이후에는 상태가 바뀔 때 갱신합니다. 전체 대화 원문이나 인증값은 저장하지 않습니다.

이 지시문은 연결된 dot이 보고 도구를 호출하도록 하는 지침입니다. 보드 자체가 모든 ChatGPT 대화를 감지하거나 dot 내부 실행 상태를 자동 조회하지 않습니다. 보고가 오래되면 실제 상태와 다를 수 있습니다. 기존 dot 예약 목록의 조회와 전체 대화에 걸친 지속적인 자동 기록은 아직 검증되지 않았습니다.

## 자동화와 예약 보고

**실제 예약과 실행은 dot의 기존 자동화 기능이 담당하고, 보드는 보고받은 상태를 표시합니다.** 이 프로젝트는 별도 스케줄러를 구현하지 않습니다. 보드의 기록을 추가하거나 수정해도 실제 자동화가 생성, 변경, 중단되거나 실행되지는 않습니다.

실제 예약은 dot의 **Scheduled**에서 확인하거나 기존 자동화 도구로 조회, 변경, 취소하도록 요청합니다. OpenAI의 [작업과 메모리 문서](https://learn.chatgpt.com/docs/dots/tasks-and-memory)를 참고하세요. 현재 작업을 멈추는 것과 이후 예약을 취소하는 것은 별개이므로, 확인한 조치와 저장된 상태만 보고합니다.

기존 예약을 가져오려면 예약 원본에 접근할 수 있는 dot 대화에서 다음과 같이 요청하세요.

> 이미 저장된 cron과 반복 예약 목록을 조회해서 이 보드에 기록해줘. 원본 예약마다 고정 카드 ID를 사용해. 보드를 채우려고 실제 예약을 새로 만들거나 변경하지 마. 확인한 예약 주기, 시간대, 활성 여부, 최근 실행, 다음 실행 시각과 결과만 기록해줘. 제공되지 않은 값은 미제공으로 표시하고 원본 예약에 접근하지 못하면 그 사실을 밝혀줘. 연결된 보드 도구가 지원하는 필드만 사용하고, 전용 필드가 없으면 예약 정보를 `summary`에 남겨줘.

보드 플러그인은 기록 저장을 제공하며, 예약 원본 조회 도구를 제공하지 않습니다. 보드를 연결해도 다른 대화나 dot의 자동화 원본을 조회할 권한이 생기지는 않습니다. 보고가 있거나 예정 시각이 지났다는 사실만으로 실행이나 성공을 확인할 수 없습니다.

## 로컬 실행

Node.js 24 이상을 권장합니다. Node.js 22.13 이상도 지원합니다.

```sh
git clone https://github.com/zzsza/openai-dots-progress-board.git
cd openai-dots-progress-board
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_yellow_iceman.sql
npm run dev -- --hostname 127.0.0.1 --port 5173
```

로컬 미리보기에서 `/signin-with-chatgpt?return_to=/`를 열면 테스트 사용자로 로그인합니다. 이 테스트 로그인은 운영 배포에 포함되지 않습니다. 이미 로컬 DB에 적용한 마이그레이션은 다시 실행하지 마세요.

```sh
npm test
npm run typecheck
npm run build
```

## 도구와 지원 필드

- `list_activity`: 보고된 진행상황과 기록된 예약 목록을 읽습니다.
- `get_activity`: 한 기록과 최근 이력을 읽습니다.
- `report_activity`: 같은 목표에 같은 ID를 사용해 새 소식을 남깁니다. 같은 내용의 반복 요청은 이력과 보고 시각을 바꾸지 않습니다. `expectedRevision`으로 오래된 기록의 덮어쓰기를 방지할 수 있습니다.

필드를 전달하기 전에 dot에 실제로 연결된 도구의 입력 스키마를 확인하세요. [저장소의 MCP 엔드포인트](app/mcp/route.ts)에는 `kind`, `schedule`, `timezone`, `scheduleEnabled`, `sourceScheduleId`, `nextRunAt`, `lastRunAt`이 정의되어 있지만, 설치된 연결 도구에는 노출되지 않을 수 있습니다. 실제 연결 도구의 스키마를 기준으로 사용하며, 소스에 있다는 이유만으로 전용 예약 필드를 지원한다고 가정하지 않습니다.

전용 필드가 없으면 지원되는 `summary`에 확인한 예약 정보를 적고, 제공되지 않은 값은 미제공으로 표시하세요. `nextCheckAt`은 보고된 다음 확인 시각이며, 자동화의 다음 실행 시각을 대신하는 필드가 아닙니다. 값을 기록해도 확인 작업이 예약되지는 않습니다. 전용 날짜나 불리언 필드를 사용할 수 있더라도 미제공이라는 문자열을 넣거나 활성 상태를 추측하지 마세요. 모르는 날짜는 비우고 미제공 정보는 `summary`에 설명합니다.

활성 여부를 모르면 `kind: schedule` 기록을 새로 만드는 대신 일반 진행상황 기록의 `summary`에 정보를 남기세요. 현재 모델은 새 예약 기록의 기본값을 활성으로 설정하므로, `scheduleEnabled`를 생략하면 미제공 상태를 올바르게 표현할 수 없습니다.

기존 자동화가 일시정지된 것을 확인한 뒤, 공통 보고 필드만 사용하는 예시입니다.

```json
{
  "id": "morning-check",
  "title": "평일 아침 일정 확인",
  "status": "paused",
  "summary": "기존 자동화가 일시정지된 것을 확인했습니다. 예약 주기: 미제공. 시간대: 미제공. 활성 여부: false. 최근 실행: 미제공. 다음 실행 시각: 미제공.",
  "nextStep": "추가로 요청된 행동이 없습니다."
}
```

## 데이터와 접근

이 앱은 인스턴스당 한 소유자를 위한 비공개 보드입니다. Sites가 브라우저와 MCP 요청을 인증합니다. 브라우저 API는 인증된 사용자 헤더와 같은 사이트의 요청도 확인합니다.

한 인스턴스를 여러 사람이 공유하는 서비스로 운영하려면 사용자별 데이터 분리가 먼저 필요합니다. 각자의 비공개 인스턴스를 사용하는 설치 방식에서는 데이터와 플러그인이 각각 분리됩니다. 저장소와 배포 소스에 API 키, 인증값, 사용자 작업 데이터를 포함하지 마세요.
